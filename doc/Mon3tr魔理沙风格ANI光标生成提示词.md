# Mon3tr / 魔理沙式 ANI 动态光标生成提示词

本文件是 QMcursor 新建角色动态光标时的唯一生图与制作要求。

目标不是制作 15 张高分辨率静态图后直接转 CUR，也不是给系统箭头换色。目标是学习 Mon3tr 与魔理沙光标的形态分布、像素语言和动画节奏，制作可由 Windows 原生播放的完整 17 角色 ANI 光标包。

生图顺序必须是：**先生成高清指针图并确认 → 询问用户选择画布档 → 再按魔理沙像素语言把高清图做成正式帧**。正式帧是在 `N×N` 上分区绘制的，不是把高清图最近邻量化后交差。禁止一上来就按 32 / 48 / 64 / 96 / 128 逻辑像素格让模型“像素风思考”，否则角色辨识度会明显变差。

## 一、固定交付规格

- 角色数：17
- 画布档：用户在高清首帧通过后五选一，整套主题共用，中途不得更换
  | 档 | 正式帧 | 颗粒 | 对齐参考 |
  |---|---|---|---|
  | 粗 | 32×32 | 大色块 | Mon3tr |
  | 中 | 48×48 | 现用密度 | 魔理沙 / 桃金娘 |
  | 细 | 64×64 | 更密 | 高清像素风 |
  | 超细 | 96×96 | 保留更多五官和服装分区 | 精细 Q 版小人 |
  | 高清像素 | 128×128 | 细节最多、屏幕占用也最大 | 高 DPI / 大号指针 |
- 每角色：8 帧
- ANI 位深：8 位索引色 + 1 位透明掩码
- 透明度：Alpha 只能为 0 或 255
- 帧间隔：`JifRate=6`，约 100ms/帧，循环约 800ms
- 轮廓：32–64 档为 1px 硬描边；96–128 档关键外轮廓可使用 1–2px 硬描边。描边色按角色选择：高对比主题可用统一近黑框；发色与肤色接近时必须用材质暗色，禁止盲套全局黑框。
- 对照缩放：只允许最近邻；禁止 LANCZOS、抗锯齿和半透明毛边。对照稿不得直接当正式帧。
- 最终文件：`Normal.ani` 至 `Pin.ani` / `Person.ani` 共 17 个

图像生成工具通常输出 1024×1024。Prompt A1 必须按**高清指针插画**生成，不要在生图描述里要求逻辑像素格、最近邻放大或 20–30 色。高清图只用于确认造型；正式帧必须在用户选定画布档后，按 Prompt A2 在 `N×N` 上执行瘦身 → 剪影 → 对照 → 分区 → 修边，不得把最近邻量化 PNG 复制为 `00.png`。

下文 `N` 表示用户确认的画布边长（32、48、64、96 或 128）。未选定前不得写入正式帧尺寸，不得进入 Prompt B。

## 二、输入

制作前读取：

1. 目标角色或主题的 4–6 张参考图。
2. Mon3tr 与魔理沙 ANI 的抽帧或帧表，用于学习构图、功能分布、像素密度和动作幅度。
3. 当前工作目录中的已有 `style-summary.md`、源帧或旧主题；旧图只能作为反例或角色资料，不能继续旧构图。

先输出并写入 `style-summary.md`：

- 角色识别元素：发型、耳朵、帽子、服装、武器、装置或代表性能力。
- 预备色板：轮廓、肤色、主色、辅色、强调色；32–64 档角色态建议 20–30 色，96–128 档可放宽到 36–48 色。分区填色后可按实际结果微调，但不得另起一套完全不同的色板。
- 眼睛构造：魔理沙式或桃金娘式，整套主题锁死一种。
- 描边策略：统一近黑框，或发色≈肤色时的材质暗色描边。
- 角色态与功能态分别采用哪些元素。
- 普通选择的热点器物、人物位置和可动部件。
- 各角色的动画语言。
- 画布档：高清首帧确认并经用户选择后，写入档名、`N×N` 和推荐热点量级。在此之前把画布档标为「待用户选择」。

## 三、必须学习的形态分布

### 1. 角色态

`Normal`、`Help`、`Working`、`Unavailable`、`Link`、`Pin`、`Person` 应优先使用完整、可辨识的 Q 版角色。

- 角色头大身小，脸部完整，双眼对称。
- 标志性道具、武器、手势或能量尖端承担功能指向。
- 角色紧邻功能尖端的右下方或下方，二者形成一个整体轮廓。
- 禁止“左上独立系统三角箭头 + 右下缩小立绘”。
- 禁止把角色立绘直接缩小粘贴。
- 不使用孤立头发、无脸头像或无法识别的人体碎片。

普通选择应学习魔理沙“扫帚尖 + 角色”和 Mon3tr“主题生物/装置直接构成指针”的思路：热点是角色动作或器物的一部分，不是额外贴上去的默认箭头。

### 2. 功能态

`Busy`、`Precision`、`Text`、`Handwriting`、四种 `Resize`、`Move`、`Alternate` 以功能骨架优先。

- 可使用帽子、耳朵、核心装置、武器切面或能力纹样做主题化。
- 不强行把完整角色塞进每一种功能指针。
- 准星、I 梁、双向箭头和四向箭头必须一眼可读。
- 功能骨架保持静止时，可以将同一帧复用 8 次；不要为了“动态”而闪烁换色。

## 四、17 个角色设计要求

1. `01-normal-select` / `Normal.ani`
   - 左上功能尖端为热点。
   - 角色与器物一体化，画面占比接近 Mon3tr / 魔理沙。
   - 8 帧有效动画：呼吸、眨眼、嘴型、耳朵/头发/衣摆/道具轻动。
   - 热点尖端全程不动。

2. `02-help-select` / `Help.ani`
   - 保留普通选择的指向结构。
   - 用角色动作、提示气泡、能力符号或道具反馈表达“帮助”。
   - 不得只贴一个孤立大问号。

3. `03-working-in-background` / `Working.ani`
   - 保留普通选择主体和热点。
   - 用环绕粒子、旋转附件、尾巴、能量环或道具节奏表达后台运行。

4. `04-busy` / `Busy.ani`
   - 中心热点，无普通箭头。
   - 学习魔理沙“帽子”与 Mon3tr“主题核心”的思路，用标志性器物或生物局部做中心循环。
   - 8 帧挤压、旋转、脉冲或形变，首尾自然。

5. `05-precision-select` / `Precision.ani`
   - 对称十字准星，中心热点。
   - 只做轻微中心脉冲；不得让准星骨架位移。

6. `06-text-select` / `Text.ani`
   - 清晰 I 梁，中心热点。
   - 可用主题色高光，通常保持静态。

7. `07-handwriting` / `Handwriting.ani`
   - 右上到左下的笔、杖、剑、羽毛或主题器物。
   - 左下尖端为热点，通常保持静态。

8. `08-unavailable` / `Unavailable.ani`
   - 可学习魔理沙 Master Spark：角色施放光束、封锁或拒绝动作。
   - 必须一眼表达“不可用”，不能只是普通选择换色。
   - 热点可位于左上功能尖端；8 帧做能量或动作循环。

9. `09-vertical-resize` / `Vertical.ani`
   - 垂直上下双向箭头，中心热点，静态。

10. `10-horizontal-resize` / `Horizontal.ani`
    - 水平左右双向箭头，中心热点，静态。

11. `11-diagonal-resize-nwse` / `Diagonal1.ani`
    - 左上—右下双向箭头，中心热点，静态。

12. `12-diagonal-resize-nesw` / `Diagonal2.ani`
    - 右上—左下双向箭头，中心热点，静态。

13. `13-move` / `Move.ani`
    - 上下左右四向箭头，中心热点，静态。

14. `14-alternate-select` / `Alternate.ani`
    - 向上指向，顶部尖端为热点，静态。

15. `15-link-select` / `Link.ani`
    - 角色使用手指、道具或能力指向热点。
    - 8 帧呼吸、眨眼和轻微动作。

16. `16-location-select` / `Pin.ani`
    - 复用 Link 的角色姿态，加入明确位置标记或定位能力附件。
    - 热点继续位于指向尖端，附件不得抢占热点。

17. `17-person-select` / `Person.ani`
    - 复用 Link 的角色姿态，加入明确人员标记或角色互动附件。
    - 热点继续位于指向尖端。

## 五、Prompt A：高清确认 → 选档 → 分区绘制像素首帧

用途：只确定指针的大方向、构图、热点和角色辨识度。此阶段不制作动画，不生成帧表。

必须按 A1 → 选档 → A2 执行。禁止把这三步合成一次生图。

将方括号替换为本主题内容。A1 的 `reference_image_paths` 必须包含全部角色参考图，以及 Mon3tr / 魔理沙首帧（只学构图，不学其像素格）。

### Prompt A1：生成高清指针首帧

```text

这是一枚真正可点击的鼠标指针，不是角色插画、头像、贴纸、立绘裁切或 UI 图标。
只生成一个首帧方案，用它确定整套指针的造型方向；不要生成动画、帧表、像素化结果或多个候选。

【画布与画风】
- 正方形高清画布，主体居中，通常输出 1024×1024。
- 按高清 Q 版指针插画绘制，让脸、发型、服装和道具尽量像参考角色。
- 使用干净的色块、清晰的材质分界和明确的轮廓，方便下一步分区绘制。
- 允许轻微体积感和分区明暗，但禁止照片风、厚涂、大面积渐变、柔光、景深、纹理噪点和抗锯齿毛边。

- 禁止给整个图像统一套棕色、黑色或白色外框。

【功能与构图】
- 点击热点位于左上方的 [武器尖端/旗杆尖端/法杖尖端/能力尖端]。
- 热点尖端必须锐利、单一、容易定位，并与角色或道具连成一个整体。

- 可动部件的填充和材质描边必须连在同一形状上；不得在形状外再留一圈重复轮廓。
- 遮挡关系必须明确：[前景部件] 位于 [中景部件] 前方，[背景部件] 位于角色后方。
- 不要使用孤立高光点、断线、透明孔洞、双重边缘或无法归属的装饰。

【角色与色板】
- 角色特征：[发型、耳朵、帽子、服装、武器、苹果、装置等]。
- 主色：[颜色列表]。
- 辅色：[颜色列表]。
- 强调色：[颜色列表]。
- 材质暗部：[分别列出头发、皮肤、服装、道具的暗部颜色]。

【背景与输出】

- 主体任何部位禁止使用背景色。
- 只输出一枚居中的普通选择高清首帧。

```

1. 目标角色的全部原始参考图。

3. 若已有用户认可的普通选择稿，把最新认可稿作为唯一构图主稿；其他旧稿只作角色资料，禁止回退旧构图。

#### A1-H 验收标准

1. 在 1024×1024 下确认角色身份、服装和热点构图。
2. 生成 256×256 缩略预览，只用于快速检查；正式转换必须继续使用 1024×1024 母版。
3. 同时在 32、48、64 像素显示尺寸下检查脸部：必须能分辨两只眼睛、嘴、头部识别纹样和抬手动作。
4. 头部视觉面积必须大于躯干和四肢；若只是人物整体变大而头身比没变，视为失败。
5. 白色或浅色热点器物必须在白底、浅灰底和深色底上都清楚。
6. 用户未确认大头比例前，不得制作其余角色或动画。

#### 高清多尺寸 CUR 后处理

仅当用户明确选择“非像素化高清静态指针”时使用；这是独立于 8 位像素 ANI 的高清静态分支。

1. 从 1024×1024 母版抠除纯色背景，保留平滑 32 位 RGBA 边缘并清除背景色溢边。
2. 从同一母版分别用 LANCZOS 输出 32 / 48 / 64 / 96 / 128 / 256 六层；禁止逐层重新生图。
3. 每层热点取左上功能尖端的最前端可见像素，并随尺寸独立写入 CUR 目录项。
4. 将六层写入同一个多分辨率静态 CUR，让 Windows 按当前系统指针大小选择最接近的一层。
5. 浅色热点器物描边在 32–128 层通常控制为 1px，256 层控制为 2px；可以使用约 75% Alpha 的深蓝灰细描边折中清晰度与粗细。
6. 人物本身不得统一加外框；若原稿已有清楚材质轮廓，直接保留。
7. 验证 `LoadCursorFromFileW` 可加载，且 CUR 内六层尺寸、热点和 32 位 Alpha 均正确。
8. 静态试用时只替换 Windows `Arrow`，其他角色保持现状，并保存应用前的 `Arrow` 注册表值以便恢复。

A1 生成后必须执行以下确认门槛：

1. 保存高清原图到 `concept/01-normal-select-hd.png`（或其他当前角色对应文件名）。
2. 展示高清图和一份缩小预览，只确认：像不像角色、热点清不清、构图是否是一体化指针。
3. 单独展示，不与像素化结果或动画预览混在一起。
4. 用户未明确确认高清构图前，禁止询问画布档，禁止像素化，禁止进入 Prompt B，禁止制作其他 16 个角色。

### 询问画布档（强制）

高清首帧通过后，必须停下来询问用户选择画布档，不得自行默认 48×48。

提供以下五档，并明确提醒 96 / 128 档会让 Windows 指针实际显示得更大：

| 档 | 正式帧 | 说明 |
|---|---|---|
| 粗 | 32×32 | 接近 Mon3tr，颗粒最大 |
| 中 | 48×48 | 接近魔理沙 / 桃金娘 |
| 细 | 64×64 | 颗粒最细 |
| 超细 | 96×96 | 适合五官、发饰和服装较复杂的完整 Q 版小人 |
| 高清像素 | 128×128 | 细节最清楚，适合高 DPI 或偏好大号指针的用户 |

用户选定后：

1. 把档名和 `N×N` 写入 `style-summary.md`。
2. 整套 17 角色必须使用同一 `N`。
3. 未选定前禁止 Prompt A2。

### 魔理沙像素语言（A2 必须对照，不复制其角色像素）

学构图和像素语言，不复制金发、扫帚或帽子造型。基准抽帧：`桃金娘光标/reference/baseline/marisa/normal/00.png`（48×48）。

| 项目 | 魔理沙 48×48 | A2 必须学到的规则 |
|---|---|---|
| 画法 | 像素原生：先剪影，再分区，再填 2–3 档色 | 禁止把高清图最近邻量化当正式帧 |
| 轮廓 | 统一 1px 近黑 `#131111` | 高对比主题可用统一近黑框；发色≈肤色时改用材质暗色描边，禁止盲套全局黑框 |
| 脸 | 干净肤色块，约 12×10 px | 脸区必须是连续肤色，不得被发色侵占 |
| 眼睛 | 每眼 3px 眼白 + 1px 眼眶 + 1px 瞳孔；中缝 2–3px 深色 | 眼睛是构造出来的：先铺眼白，再加眼眶和瞳孔；发色绝不贴眼白 |
| 材质 | 单材质 2–3 档明暗 | 发 / 肤 / 衣 / 器物各限 2–3 色，禁止跨区借色 |
| 省略 | 手指纹理、帽褶、渐变 | 像素预算先于细节；装不下的装饰在瘦身阶段删掉 |
| 负空间 | bbox 约 (2,5)–(46,45)，1–2px 安全边 | 主体不得贴边；热点尖端单像素收束 |
| 器物 | 扫帚 2px 实心（填充 + 描边） | 细长热点器物 2px：一侧暗、一侧亮 |

Mon3tr 32×32 是「更满、更依赖纯黑、大白眼块」的粗档参考。桃金娘 48×48 证明发色接近肤色时，可用材质暗描边 + 无眼白简眼替代全局黑框。

眼睛构造整套主题必须锁死一种，写入 `style-summary.md` 后不得中途更换：

- **魔理沙式（默认）：** 每眼 2×2 或 3×2 眼白 + 1px 眼眶 + 1px 瞳孔；两眼中缝 ≥2px。脸更可读。
- **桃金娘式（备用）：** 无眼白，1–2px 深色点直接点在肤上。仅当发色极度挤占脸区、眼白块放不下时使用。

**失败反例（禁止再犯）：** 安洁莉娜 48×48 曾把 1024 母版交给 `image_to_pixel_art_wasm` 做最近邻 + 30 色量化。脸区被发色 `#AD7260` 侵占，眼白 `#FFF8EA` 不成块，发 / 肤 / 眼棕在同一网格竞争代表色。色数够（约 26 色），缺的是 1px 语义隔离。该稿只可保留为对照反例，不得当 `00.png`。

### Prompt A2：按所选档分区绘制像素首帧

A2 不是再次调用生图模型重画角色，也不是把高清图压成马赛克。输入是已确认的高清图、用户选定的 `N`、预备色板，以及魔理沙 / Mon3tr 抽帧（只学像素语言）。

必须按 A2-0 → A2-1 → A2-2 → A2-3 → A2-4 → A2-5 执行。禁止把六步合成一次量化。`image_to_pixel_art_wasm` 或任何全局调色板工具的输出只能进 `concept/pixel-ref/`，禁止复制为 `source/*/00.png`。

#### A2-0 高清瘦身

在已确认的 1024 母版上删掉 `N` 档装不下的细节，不改变构图、热点方向和角色身份，不重新生图。

- 脸改为平涂 2 档肤色；虹膜改成可构造的色块，去掉渐变、双高光、细腮红线。
- 发带纹样、袖褶、尾毛分缕、多层高光等装饰，若压到 `N` 后会小于 2px 或与邻色黏连，一律删除或合并成单色块。
- 48×48 脸区预算大约只剩 10×8；必须先保证眼、耳、热点器物，再考虑嘴和发带细节。
- 输出 `concept/<role>-hd-simplified.png`，仍为高清 RGBA，不是像素格。

48×48 识别优先级（高 → 低），低优先级可省略：

1. 热点器物尖端（2px 实心，热点单像素）
2. 对称双眼（中缝 ≥2px）
3. 头部识别元素（兽耳、帽子、发带色块）
4. 标志性头发或尾巴的外轮廓体积
5. 服装大分区（如白袖 / 深衣）
6. 纹样减到 1–2 个色点
7. 嘴、腮红、分缕、衣褶：可省略

#### A2-1 剪影

在空白 `N×N` 上只用最深轮廓色画出主体剪影和透明底。

- 确认热点尖端、耳 / 帽 / 马尾 / 身体 / 器物连通。
- 四周留 1–2px 安全边，任何像素不得贴边或被裁切。
- 此步不填内部色；只解决「形状是否装得下」。
- 输出 `concept/<role>-silhouette-N.png`。

#### A2-2 对照稿（非正式帧）

仅对瘦身后的透明高清图做最近邻缩放到 `N×N`，可选再映射到固定色板，作为色块位置参考。

- 推荐 `gametorch/image_to_pixel_art_wasm`；输出必须写入 `concept/pixel-ref/`。
- 禁止 LANCZOS、双三次、抗锯齿。
- 禁止把对照稿当作修边起点直接涂改成交稿；正式像素从剪影填色，对照稿只用来核对着色区域。

```powershell
node tools/image_to_pixel_art_wasm/pixelate-images.mjs `
  --palette <固定色板HEX> `
  concept/<role>-hd-simplified-transparent.png `
  concept/pixel-ref `
  N
```

#### A2-3 分区填色

在剪影上按语义分区填固定色板，每区 2–3 档明暗。

- 分区至少包括：热点器物、头发、脸/肤、眼睛、服装、强调色。
- 相邻近色材质之间先画 1px 分隔，再填两侧色。发色不得侵入脸区，脸区不得借用发色。
- 禁止跨区借色（例如用发色填眼眶、用肤色填飞机）。
- 32–64 档角色态 20–30 色；96–128 档 36–48 色。

#### A2-4 修边

- 32–64 档内部五官和材质分界保持 1px；96–128 档外轮廓可 1–2px。
- 轮廓色属于相邻材质的深色：头发用深发色，旗布用深旗色，衣服用深衣色，浅色器物用灰或相邻深色。
- 高对比主题可学魔理沙使用统一近黑 1px 框；发色与肤色接近时禁止全局套黑框、白框或棕框，否则会再吞一圈脸。
- 眼睛按主题锁定的构造方式绘制：魔理沙式先铺眼白再点瞳；桃金娘式在肤上点深色瞳。两眼中缝不得被刘海或发色切断。
- 细长热点器物 2px 宽实心（一侧暗色，一侧填充或高光），尖端收束为单像素热点。
- 删除孤立过渡色、透明洞、双重边缘。

#### A2-5 门槛

正式输出是一张 `N×N` 的 `00.png`。原生 `N`px 与最近邻整数倍放大预览必须同时通过：

1. 眼白或瞳孔可数，两眼对称，中缝 ≥2px。
2. 发 / 肤之间有 1px 隔离；发色不贴眼白。
3. 功能尖端清楚、实心、可作为热点。
4. 角色和道具不粘成无法辨认的色团。
5. Alpha 仅 0/255；颜色全部来自固定色板。

脸糊、眼无中缝、发贴眼白、量化稿直接当首帧，均视为失败，不得进入 Prompt B。

```text
任务：把已确认的高清指针首帧做成 [主题名] 的 [角色名] 正式像素首帧。

高清图是唯一造型来源。禁止重新设计角色、重画脸、改变构图或再生成一张新的像素风图。
禁止把高清图最近邻量化、调色板抖动或 WASM 输出当作 `00.png`。
正式输出是一张 N×N 的 `00.png`，N = [32 / 48 / 64 / 96 / 128]。
必须按 A2-0 瘦身 → A2-1 剪影 → A2-2 对照 → A2-3 分区 → A2-4 修边执行。

【像素语言】
- 学魔理沙：硬边、分区、2–3 档明暗、眼睛构造出来而不是压出来。
- 像素预算先于细节；装不下的渐变、双高光、细纹、分缕在瘦身阶段删除。
- 相邻近色必须 1px 硬切；发色与肤色接近时用材质暗色描边，不要全局黑框。
- 眼睛锁定 [魔理沙式 / 桃金娘式]；中缝 ≥2px；发色绝不贴眼白。
- 单材质 2–3 色；禁止跨区借色。

【对照稿】
- 最近邻缩放只用于 `concept/pixel-ref/` 对照。
- 禁止 LANCZOS、抗锯齿、半透明毛边。
- WASM / 全局量化 PNG 不是正式帧。

【形状与热点】
- 主体四周 1–2px 安全边距，任何像素不得贴边。
- 热点尖端收束为单一锐利点；细长器物 2px 宽实心（一侧暗色，一侧填充或高光）。

【必须保住的内容】
- 高清图中的构图、热点方向、角色识别特征和遮挡关系。
- 脸是连续肤色块；双眼完整对称，可数清眼白或瞳孔。
- 可动部件边界仍然完整，颜色归属明确。
- 原生 Npx 下仍能识别：[按优先级列出 3–5 个角色识别特征]。
```

A2 完成后必须执行以下确认门槛：

1. 输出 `N×N` 的 `00.png`，以及最近邻整数倍放大预览。对照稿留在 `concept/pixel-ref/`，不要和正式帧混放。
2. 检查热点、脸、双眼（眼白/瞳孔可数、中缝隔离）、发肤 1px 分隔、手、道具、可动部件边界和前后遮挡。
3. 单独展示像素首帧，不与动画预览或 WASM 对照稿混在一起。
4. 大图好看但原生 `N`px 糊成一团、发贴眼白、角色无法辨识或功能尖端不清楚，均视为像素化失败；应回到 A2-0 继续瘦身或请用户换档，不得把量化稿修一修就当完成，不得直接进入 Prompt B。
5. 用户未明确确认像素首帧前，禁止进入 Prompt B，禁止制作其他 16 个角色。

其余 16 个角色同样走 A1 → 同一画布档 → A2-0 至 A2-5，不得改用别的 `N`，也不得跳过高清确认或跳过剪影/分区，直接像素风生图或量化交差。

### 高精细 Q 版小人实战流程（96 / 128 档）

当 64×64 无法保住完整双眼、发饰、服装分区或大型尾发时，仍走完整 A2-0 至 A2-5，只是对照稿尺寸改为 96 / 128。WASM 只生成 `concept/pixel-ref/` 对照，不得当正式帧。此流程曾用于安洁莉娜小人 128×128 首帧验证；该主题最终改走高清静态 CUR，头太小的旧稿和全部像素档已删除。安洁莉娜后来的 48×48 WASM 量化稿再次证明：跳过剪影和分区会让脸与眼睛黏成一团。

1. **只把缩略图用于预览**
   - 保留 `concept/01-normal-select-hd.png` 的 1024×1024 高清母版。
   - 可以另存 256×256 的 `preview/*-hd-small.png` 供聊天和快速查看，但禁止把该缩略图作为 A2-0 瘦身或对照输入。
   - 从 256×256 缩略图压到 96 / 128 会提前丢失眼睛、发带、衣纹和细线，画布变大也无法恢复。

2. **先做 A2-0 瘦身并抠除纯色背景**
   - 在高清母版上删掉 96 / 128 仍会黏连的渐变和细纹，再抠出 RGBA 前景。
   - Alpha 二值化为 0 / 255，透明区域 RGB 清零。
   - 检查角色、纸飞机、轨迹或其他热点器物没有被误删。

3. **使用确定性工具生成 96 / 128 对照（非正式帧）**
   - 推荐使用 `gametorch/image_to_pixel_art_wasm`；输出必须写入 `concept/pixel-ref/`。
   - 对同一张瘦身后的透明高清图分别输出 96×96、128×128，禁止先生成 96 再放大到 128。
   - 首次从瘦身稿提取或使用固定色板；第二个尺寸复用完全相同的色板，使对比只反映画布差异。
   - 缩放与回写只使用最近邻。对照稿尺寸等于候选 `N×N`，但不得把对照稿或放大预览误当正式帧。
   - 示例命令（工具包装脚本位于主题工作目录时）：

```powershell
node tools/image_to_pixel_art_wasm/pixelate-images.mjs `
  --auto-colors 48 `
  concept/input-transparent.png `
  concept/pixel-ref `
  96 128
```

4. **同时检查原生尺寸和整数倍预览**
   - 96 档建议生成 ×8 预览，128 档建议生成 ×6 或 ×8 预览。
   - 对比脸、双眼（眼白/瞳孔是否可数）、耳朵、发带纹样、手、脚、尾发、衣服分区和热点器物。
   - 放大预览只用于逐像素检查；是否可用仍以原生 96 / 128 像素显示为准。
   - 若对照稿已经发贴眼白或脸糊成团，说明必须先回到 A2-0 继续删细节，而不是在糊图上修边。

5. **选择档位后立即锁定**
   - 把用户选定的 `N` 写入 `style-summary.md`，整套 17 角色统一使用。
   - 同时写入固定色板、眼睛构造方式（魔理沙式或桃金娘式）、描边策略、热点坐标、可动部件和安全边距。
   - 128 档通常比 96 档更清楚，但实际 Windows 指针也更大；必须让用户明确选择，不得替用户默认。

6. **从剪影分区绘制，再按需修正左上热点器物**
   - 正式帧从 A2-1 剪影填色，不从 WASM 对照稿涂改。
   - 若纸飞机、扫帚尖、武器尖端或能力尖端相对人物过小，只调整该器物，不缩放整个人物。
   - 从 Alpha 连通域或明确蒙版提取热点器物，以点击尖端为固定锚点，通常放大到原来的 1.2–1.35 倍。
   - 左上热点器物只能向右下扩展；热点坐标不得移动。安洁莉娜示例把纸飞机从约 18×13 放大到约 24×17，热点保持 `[10, 15]`。
   - 放大后重新连接轨迹或手势，避免器物变成与人物无关的独立默认箭头。
   - 所有调整必须写入 `build_assets.py` 或主题专用确定性脚本，禁止只手改一张临时 PNG。

7. **最后按 A2-4 人工修边**
   - 清理眼睛不对称、轮廓台阶、孤立像素、透明洞、断裂轨迹和粘连色团。
   - 强制补 1px 发/肤隔离和眼白中缝；发色不得贴眼白。
   - 96 / 128 档允许关键外轮廓为 2px，但内部五官和材质分界应尽量保持 1px。
   - 不增加色板外颜色；修完后重新验证尺寸、硬 Alpha、色数、热点和安全边距。

8. **确认后固化正式首帧**
   - 保存为 `concept/size-candidates/N/00.png` 并生成整数倍预览。
   - 用户确认后再复制为 `source/01-normal-select/00.png`，随后才能进入 Prompt B。
   - 记录转换输入、工具、色板、器物调整前后尺寸和热点坐标，保证后续 16 个角色可复用同一流程。
   - `concept/pixel-ref/` 中的 WASM 文件保持为对照，不得覆盖 `source/`。

## 六、Prompt B：基于首帧制作后续动画

用途：像素首帧确认后，以 `00.png` 为唯一造型底稿制作 `01.png` 至 `07.png`。这是一段逐像素分层、变形和合成任务 Prompt，不是让生图模型重新绘制七张图。

输入必须包含：

- 已确认且不得改动的 `N×N` `00.png`。
- 固定热点坐标 `[HOTSPOT_X, HOTSPOT_Y]`。
- 固定色板。
- 用户确认的动作描述。
- 明确的固定层、可动层和遮挡层列表。

```text
任务：基于已确认的 N×N 像素首帧 `00.png`，制作 [角色名 / 指针角色] 的 8 帧循环动画。N = [32 / 48 / 64 / 96 / 128]。

`00.png` 是唯一造型标准。禁止重新设计角色、重画脸部、改变比例、改变轮廓语言或重新生成每一帧。
正式输出必须保留原始 `00.png`，只派生 `01.png` 至 `07.png`。

【第一步：先拆层，不得直接做动画】
把首帧按明确像素蒙版拆成：
1. 固定热点层：[旗杆尖端/武器尖端/功能骨架]。
2. 固定人物层：[脸、身体、必须静止的部位]。
3. 可动层：[眼睛、嘴、耳朵、头发、衣摆、旗布、尾巴、苹果等]。
4. 背景补底层：储存可动部件移开后应露出的正确像素。
5. 前景遮挡层：始终覆盖在可动部件前方的角色或道具。

必须先输出每个分层蒙版的透明 PNG 预览和合成回放。
所有蒙版叠回后必须与 `00.png` 逐像素完全一致。
禁止仅凭“棕色、白色、深色”等颜色自动猜部件归属；
同色但属于不同部件的像素必须使用手工区域、连通域或明确坐标蒙版区分。

【固定内容】
- 画布始终为 N×N，热点始终为 `[HOTSPOT_X, HOTSPOT_Y]`。
- 固定热点层在全部 8 帧中的位置、Alpha、颜色和轮廓逐像素完全一致。
- 禁止整个人物层统一上下平移、左右抖动、缩放或旋转。
- 禁止通过改变透明画布裁剪范围制造假动画。

【本次动作设计】
- 主动作：[例如整面旗布随风飘动]。
- 次动作：[例如第 3–5 帧眨眼一次]。
- 辅助动作：[例如发梢、耳朵、苹果在 0–1px 范围内错相轻动]。
- 最大位移：[32 档 1px；48 档 1–2px；64 档 1–3px；96 档 2–4px；128 档 2–5px]。
- 循环节奏：[平静 → 展开 → 最大形变 → 回弹 → 反向小形变 → 回到首帧]。

若动画对象是旗帜、披风、尾巴或布料：
- 固定连接点不动，距离连接点越远，位移幅度逐渐增大。
- 填充、暗部、高光和材质描边必须作为同一个部件一起变形。
- 旧位置的整套部件像素必须同时移走，不得留下静止的旧轮廓、白线或深色框。
- 部件移开后必须显示背景补底层或被遮挡的角色层，禁止直接挖成透明洞。
- 新位置不得凭空增加轮廓；边缘色必须来自该材质自己的暗部色。
- 形变后保持连通，不得出现断线、裂缝、双重边缘、孤立白点和悬空像素。

【8 帧节奏】
- 00：已确认首帧，完全不改。
- 01：动作起始，主动作幅度约 25%。
- 02：动作展开，幅度约 60%。
- 03：第一极值，幅度约 100%。
- 04：回弹经过中位，配合一次次动作。
- 05：反向极值，幅度约 60%–80%。
- 06：回收，幅度约 40%。
- 07：接近首帧，保证 07 → 00 不跳变。

相邻帧变化应集中在指定可动层，不得靠全图闪色或整体位移制造动态。

【输出】
- `00.png` 至 `07.png`：8 张 N×N RGBA PNG。
- `layers/`：固定层、每个可动层、背景补底层、前景遮挡层。
- `preview-sheet.png`：8 帧横向帧表，最近邻放大。
- `preview.gif`：约 100ms/帧循环预览，使用固定调色板，禁止自适应调色造成闪色。默认铺浅绿色棋盘背景（建议 `#B6D2B8` / `#92B898`）以暴露透明洞；若主题主体本身以绿色为主，改用与主体有明显明度、色相差异的棋盘背景。
- `diff-sheet.png`：标记每帧相对 `00.png` 的变化区域。

【生成后强制验证】
- `00.png` 与已确认首帧逐像素相同。
- 8 帧均为 N×N，Alpha 只含 0/255，颜色全部来自固定色板。
- 热点层 8 帧逐像素相同。
- 固定人物层没有整体位移。
- 可动部件原位置不存在静止残影、旧外框或旧白线。
- 可动部件新位置不存在透明洞、断线、孤立亮点和重复轮廓。
- 相邻帧有有效变化，07 → 00 的差异不大于循环中的普通相邻帧。
- 原生 Npx 与放大预览都必须检查。

只生成 PNG 分层、8 帧和预览；暂时不要构建 ANI，不要同步 QMcursor，不要替换系统指针。
必须先把分层预览、帧表和 GIF 展示给用户确认，确认后才允许打包。
```

Prompt B 的关键原则是“首帧锁定、蒙版明确、像素派生”。禁止对七个续帧分别调用生图模型；模型只能辅助提出动作方案，正式帧必须由已确认像素首帧通过逐像素编辑或确定性脚本派生。禁止用高清图逐帧重生后再分别像素化。

### 动画清理与人工验收经验

以下规则来自桃金娘 Normal 多轮修正，后续角色态动画均应复用。

#### 1. 区分“旧外框”和“主题部件”

- 把黑色、棕色旧外框换成紫色、灰色或材质暗色，不等于去除外框；原来的外框像素壳仍然存在。
- 只删除能够确认属于旧外框壳、且删除后不会切断细线或肢体连接的像素。删除后暴露出的内线必须改成相邻材质自己的暗色。
- 旗面、披风、头发等浅色部件伸出角色轮廓时，视觉上可能像“白边”，但它们不一定是外框。不得为了消除白边感而整体裁掉主题部件。
- 清理后必须核对部件语义是否完整，例如旗帜右侧自由端仍然存在、披风没有被削成窄条、耳朵和发梢没有被误删。
- 角色与背景部件难以分开时，优先在交界处增加 1–2px 的材质暗色分隔，不要直接挖透明沟槽。

#### 2. 固定器物必须实心

- 旗杆、法杖、剑、笔等承担热点的细长器物，中心线必须全程实心，禁止用交替色块画出看似空心的管状结构。
- 1px 像素风下建议使用 2px 宽结构：一侧为材质暗色，另一侧为填充或高光色；尖端可收束为单像素热点。
- 固定器物的坐标、Alpha 和颜色必须在 8 帧逐像素相同。验证时单独提取固定器物层，检查中心线上不存在 Alpha 0。
- 器物与旗布、披风等连接处应按行渐进展开，形成 1px 阶梯过渡；禁止从窄杆突然跳成大色块。

#### 3. 透明洞必须按拓扑检查

- 绿色棋盘背景比黑底更容易暴露旗面、浅色衣物和器物内部的透明洞。每轮修改后都要同时检查原生 Npx、最近邻放大帧表和 GIF。
- 从画布四边对透明像素做洪水填充；无法连到画布外部的透明连通域属于“封闭透明洞”。旗面、器物和角色实体内部的封闭透明洞数量必须为 0。
- 对旗杆右侧、旗布根部、披风遮挡区等已知高风险区域，额外限制检测坐标范围，防止细长锯齿空腔漏检。
- 可动旗面产生的短缺口必须在当前帧的变形旗布层上修补。禁止用一组固定坐标覆盖全部帧，否则旗面移动后补丁会悬空或被连通域清理掉。
- 修补颜色来自该部件的填充色或暗部色；不得用纯黑、纯白或背景色填洞。

#### 4. 删除异常像素时不得制造新洞

- 发现头发、呆毛、旗面附近的孤立黑点、绿点或白点时，先判断它属于背景、旧外框还是错误材质。
- 若异常像素位于实体内部，应替换为周围材质色，而不是直接设为透明；直接清除可能把“黑点”变成背景可见的绿色洞。
- 清理后重新运行孤立亮点、透明洞、连通域和固定层检查，不能只确认目标像素已经消失。
- 变形后产生的 1–4px 离散连通域通常是残影或映射碎片；确认不属于角色识别细节后才能删除。

#### 5. 每轮修改都要形成完整反馈闭环

1. 修改确定性生成脚本，不直接手改七张续帧。
2. 重新生成 8 张正式帧、原生帧表、最近邻放大帧表、差异图和 GIF。
3. 在绿色棋盘背景上人工查看：热点器物、旗面/披风完整性、脸、双眼、头发、四肢、透明洞、残影和循环首尾。
4. 再运行自动验证：硬 Alpha、透明区 RGB 清零、固定层一致、颜色数、有效帧数、连通率、孤立亮点和封闭透明洞。
5. 自动断言通过但放大图仍有明显缺陷，视为未通过；继续修改并重新生成。
6. 每次动画改好后，回复中必须直接展示本轮最新 GIF，不得只提供文件路径、静态 PNG 或文字报告。
7. 用户确认当前 GIF 后，才能同步 `source/`、重建 ANI、更新 QMcursor 或应用到 Windows。

用户确认 `Normal` 动画后，再按顺序制作其余 16 个角色。每个新角色仍先确认自己的高清构图，再按同一画布档走 A2-0 至 A2-5，再进入续帧制作。

## 九、强制验证

- 正好 17 个角色目录、每目录正好 8 张 PNG。
- 所有帧均为用户确认的 `N×N` RGBA。
- Alpha 只含 0/255；透明区域无品红、白边、黑边污染。
- 角色态色数不超过 255；32–64 档推荐 20–30 色，96–128 档推荐 36–48 色。
- 同一角色全部帧热点相同且位于可见功能尖端。
- 固定热点器物中心线全帧实心，固定层坐标、Alpha 和颜色逐像素一致。
- 旗面、披风、衣物、器物等实体区域不存在无法连到画布外部的封闭透明洞。
- 不存在 1–4px 的无归属离散连通域；角色主体与主题器物保持完整。
- 清理旧外框后，旗帜自由端、披风、耳朵、发梢等语义部件未被过度裁切。
- Normal、Help、Working、Busy、Unavailable、Link、Pin、Person 至少有 4 个不同有效帧。
- Text、Handwriting、Resize、Move、Alternate 允许 8 帧相同。
- 每个动态角色均已生成绿色棋盘背景 GIF、原生帧表、最近邻放大帧表和差异图，并完成逐帧人工查看。
- ANI 是合法 RIFF `ACON`，包含 8 个 CUR 帧，8 位，`JifRate=6`，尺寸为 `N×N`。
- `LoadCursorFromFileW` 能加载全部 17 个 ANI。
- QMcursor 能导入并应用传统 15 角色；Pin / Person 仍随包保留。
- 应用后关闭 QMcursor，动画仍由 Windows 播放。

## 十、禁止事项

- 禁止使用已删除的旧静态指针 Prompt 或旧 Skill。
- 禁止生成 15 张高分辨率静态 PNG 后直接转 CUR。
- 禁止在用户确认高清构图前像素化或询问画布档。
- 禁止未询问用户就默认 48×48 或其他画布档。
- 禁止让生图模型直接按逻辑像素格输出“像素风指针”作为首帧。
- 禁止把最近邻量化、调色板抖动或 `image_to_pixel_art_wasm` 输出当作 `00.png` 或任何正式帧。
- 禁止发色贴眼白、无中缝、脸区被头发侵占仍进入 Prompt B。
- 禁止用高清图逐帧重生后再分别像素化来制作动画。
- 禁止多分辨率 CUR、32 位软边 ANI、LANCZOS 缩放。
- 禁止默认系统箭头加角色贴纸。
- 禁止所有角色都采用同一个箭头再叠问号/转圈。
- 禁止每帧重新生图造成脸、衣服、比例和热点漂移。
- 禁止半透明像素、抗锯齿、色键溢色和无意义闪烁。
